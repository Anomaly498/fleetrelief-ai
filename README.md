## 📌 Overview & Vision

Urban public transit networks experience severe cascading delays when sudden mechanical failures (radiator blowouts, axle breaks, tire leaks) occur on crowded corridors. Drivers struggle to communicate detailed diagnostics under pressure, central depot dispatchers lose critical minutes evaluating operational response, and commuters are left stranded without actionable delay information.

**FleetRelief AI** resolves this emergency bottleneck by serving as the autonomous reasoning bridge between three transit stakeholders:
1. **The Field Driver:** Ingests raw, unstructured incident reports in any script or dialect (English, Bengali, Hindi, Banglish, Hinglish) without requiring cumbersome multi-field forms[cite: 1].
2. **The Transit Dispatcher / Depot Authority:** Evaluates incident severity (`LOW`, `MEDIUM`, `HIGH`) and generates immediate containment actions (dispatching wreckers, assigning standby shuttles, or rerouting subsequent lines).
3. **The Commuter / Passenger:** Synthesizes localized, human-readable service advisories in real time, supporting code-mixed colloquial dialects (Banglish/Hinglish) and clean English reference translations for arrival timelines[cite: 1].

## 🛠️ Tech Stack

* **AI & Cloud Engine:** Amazon Bedrock (`amazon.nova-lite-v1:0` via `@aws-sdk/client-bedrock-runtime`)
* **Backend Runtime:** Node.js, Express.js, CORS, Dotenv[cite: 1]
* **Cloud Hosting:** Vercel (Serverless Functions)
* **Authentication:** AWS HTTP Bearer Auth integration (`httpBearerAuth`)
* **Frontend UI:** HTML5, Modern Vanilla JavaScript, Tailwind CSS[cite: 1]

---

## 💡 Key Technical Highlights

* **Few-Shot Dialect Steering:** Directs the foundation model to construct natural, single-sentence code-mixed vernaculars in the Latin/Roman script (e.g., Romanized Banglish or Hinglish) rather than mechanical script-followed-by-translation patterns.
* **Stream Buffer Sanitization:** Implements regex-driven response filtering to eliminate markdown code fences (````json ... ````) generated by foundation models, preventing JSON parsing syntax errors and ensuring high API uptime.
* **Optimized Serverless Inference:** Bypasses third-party Marketplace subscription hurdles and international payment pre-authorization constraints by leveraging AWS-native Amazon Nova Lite foundation models.
* **Hybrid Serverless Compatibility:** Configured with `process.cwd()` absolute path resolution and conditional `app.listen()` wrappers to run consistently across both local Node runtimes and Vercel serverless execution layers.

## 🚀 Getting Started

### 1. Prerequisites
* Node.js (v18 or higher)
* Active AWS Account with Bedrock model access enabled for **Amazon Nova Lite**

### 2. Local Installation

Clone the repository and install dependencies:

```bash
git clone [https://github.com/Anomaly498/fleetrelief-ai.git](https://github.com/Anomaly498/fleetrelief-ai.git)
cd fleetrelief-ai/fleetrelief-backend
npm install

```

### 3. Environment Configuration

Create a `.env` file in the project directory:

```env
PORT=5000
AWS_REGION=us-east-1
BEDROCK_API_KEY=your_bedrock_api_key_here

```

### 4. Run Locally

Launch the Express server:

```bash
node server.js

```

Open your browser and navigate to:

```text
http://localhost:5000

```

## 🌐 Cloud Deployment (Vercel)

This repository includes a native `vercel.json` rewrite configuration that enables Express to run serverlessly on Vercel:

1. Push your repository to GitHub.
2. Import the project into your **Vercel Dashboard**.
3. Under **Project Settings → Environment Variables**, add:
    * `AWS_REGION`: `us-east-1`
    * `BEDROCK_API_KEY`: Your Amazon Bedrock Bearer Token
4. Deploy. Vercel automatically exposes the static administrative client at `/` and the incident handler at `/api/agent/incident`.

## 📡 API Reference

### Trigger Autonomous Dispatch Triage

* **Method:** `POST`
* **Local Endpoint:** `http://localhost:5000/api/agent/incident`
* **Production Endpoint:** `https://fleetrelief-ai.vercel.app/api/agent/incident`
* **Headers:** `Content-Type: application/json`

#### Request Body

```json
{
  "driverReport": "শ্যামবাজার পাঁচমাথার মোড়ের কাছে গাড়ির পেছনের বাইরের দিকের টায়ারে বাতাস ধীরে বেরিয়ে যাওয়ার সমস্যা ধরা পড়েছে। কম গতিতে ২ কিলোমিটার পর্যন্ত গাড়িটি চালানো নিরাপদ; তাই পরবর্তী নির্ধারিত টার্মিনালে টায়ার মেরামতের দলকে বাসটির সাথে দেখা করার অনুরোধ জানানো হচ্ছে।",
  "routeName": "Howrah - Salt Lake",
  "targetLang": "BILINGUAL_DIALECT"
}

```

| Parameter      | Type     | Required |                       Description                          |
| ---            | ---      | ---      | ---                                                        |
| `driverReport` | `string` | **Yes**  | Natural-language incident description from the driver.     |
| `routeName`    | `string` | No       | Route or corridor name (defaults to `"General Corridor"`). |
| `targetLang`   | `string` | No       | `"BILINGUAL_DIALECT"`, `"MATCH_INPUT"`, or `"ENGLISH"`.    |

#### Sample Response (`200 OK`)

```json
{
  "success": true,
  "agentDispatch": {
    "severity": "MEDIUM",
    "detectedLanguage": "Bengali",
    "summary": "Slow air leak detected on rear outer tire near Shyambazar Panchmatha Mor, safe to proceed at reduced speed.",
    "immediateAction": "Dispatch mobile tire maintenance crew to intercept vehicle at the next scheduled terminal.",
    "passengerNotice": "Shyambazar Panchmatha Mor er kache rear outer tyre e slow air leak issue detect hoyeche. Bus slow speed e next terminal pouchache, repair team ready ache.",
    "passengerNoticeEnglish": "A slow air leak has been detected in the rear outer tire near Shyambazar Panchmatha Mor. The bus is operating at reduced speed to the next terminal for repair."
  }
}

```
